VPN(가상사설망)

회사 밖에서 들어오는 문 · 본문 2장, 6장

어디에 서 있나

VPN 장비는 회사 입구, 방화벽 곁에 섭니다. 재택근무자나 출장 중인 직원은 인터넷을 거쳐 VPN 장비에 접속하고, 인증을 통과하면 암호화된 통로(터널)를 얻습니다. 그 뒤로 직원 노트북의 통신은 이 통로를 타고 회사 안으로 들어가므로, 바깥에 있어도 회사 내부망에 앉아 있는 것처럼 업무 시스템을 씁니다.

VPN은 두 가지로 많이 씁니다. 본사와 지사처럼 네트워크와 네트워크를 상시로 잇는 데는 IPsec VPN을, 직원 한 사람이 노트북이나 휴대폰으로 접속하는 데는 웹 브라우저나 전용 프로그램으로 붙는 SSL VPN을 주로 씁니다.

무엇을 보고 판단하나

먼저 사람을 확인한다

VPN의 판단은 대부분 접속하는 순간에 일어납니다. 아이디와 비밀번호를 확인하고, 요즘은 휴대폰 승인이나 일회용 번호 같은 두 번째 확인(다중 인증, MFA)을 더합니다. 일부 제품은 접속하려는 노트북이 회사가 지급한 기기인지, 백신이 켜져 있는지도 함께 봅니다. 확인은 VPN 장비가 직접 하기도 하지만, 대개 회사의 계정 서버에 물어봅니다. 이때 장비와 계정 서버가 주고받는 표준 약속이 RADIUS입니다. RADIUS는 다음 장의 NAC에서도 다시 나옵니다.

통로를 열고, 범위를 좁힌다

인증을 통과하면 VPN은 그 사용자에게 회사 내부망에서 쓸 주소 하나를 빌려줍니다. 이후 그 사용자의 통신은 모두 이 내부 주소로 찍힙니다. 통로를 연 뒤에는 사용자가 회사 안의 어디까지 갈 수 있는지를 정해야 합니다. 영업 직원에게는 메일과 영업 시스템만, 서버 관리자에게는 서버 구역까지 여는 식입니다. 이 범위를 넓게 열어 두면, VPN 계정 하나를 빼앗긴 것만으로 공격자가 회사 내부망 전체를 돌아다닐 수 있습니다.

전체 그림에서의 뜻

VPN은 1990년대에 「회사 밖의 직원도 회사 안에 있는 것처럼」이라는 요구에서 나왔습니다. 경계 안은 믿는다는 생각 위에 선 장비입니다. 본문 6장의 시대에 원격근무가 일상이 되자 이 생각이 약점이 됐습니다. 피싱으로 훔친 계정으로 VPN에 로그인하면 방화벽 입장에서는 허용된 직원의 접속입니다. 제로트러스트는 이 약점에서 출발해, 통로에 들어왔다는 이유로 믿지 않고 시스템에 접근할 때마다 사람과 기기와 권한을 다시 확인하자고 합니다.

로그로 읽기

VPN 로그의 중심은 「누가 언제 들어와서 어떤 내부 주소를 받아 얼마 동안 무엇을 주고받았나」입니다. 이 내용은 RADIUS 회계(Accounting) 기록에 잘 드러납니다. 접속을 시작할 때 Start 기록이, 끝낼 때 Stop 기록이 남습니다. 아래는 RFC 2865·2866이 정한 속성 이름으로 쓴 설명용 예시입니다. 계정과 값은 꾸민 것입니다.

# 접속 시작
Acct-Status-Type = Start
User-Name = "kim.jh"
Framed-IP-Address = 10.200.0.15
Acct-Session-Id = "4D2A0019"

# 접속 종료
Acct-Status-Type = Stop
User-Name = "kim.jh"
Framed-IP-Address = 10.200.0.15
Acct-Session-Id = "4D2A0019"
Acct-Session-Time = 5400
Acct-Input-Octets = 18350211
Acct-Output-Octets = 402998310
Acct-Terminate-Cause = User-Request

속성 뜻: RFC 2866, RADIUS Accounting(2000년 6월). Framed-IP-Address, User-Name은 RFC 2865.

속성예시 값읽는 법
Acct-Status-TypeStart / Stop서비스의 시작인지 끝인지.
User-Namekim.jh누가.
Framed-IP-Address10.200.0.15이 사용자에게 빌려준 내부 주소. 이 접속이 이어지는 동안 회사 안의 다른 장비 로그에는 사람 대신 이 주소가 찍힙니다.
Acct-Session-Id4D2A0019Start와 Stop을 짝지어 주는 번호.
Acct-Session-Time5400접속해 있던 초. 5,400초는 1시간 30분입니다. Stop 기록에만 있습니다.
Acct-Input-Octets / Acct-Output-Octets약 18MB / 약 403MBRFC 2866의 정의로 Input은 사용자 쪽에서 받은 양, Output은 사용자 쪽으로 보낸 양입니다. 이 예에서는 사용자가 회사 쪽에서 약 403MB를 내려받았습니다.
Acct-Terminate-CauseUser-Request어떻게 끝났나. 사용자가 직접 끊었습니다.

제품의 자체 로그에는 여기에 더해, 사용자가 접속해 온 바깥 주소와 인증 성공·실패, 실패 사유가 남습니다.

이 로그로 답할 수 있는 질문

  • 내부 주소 10.200.0.15는 그 시각에 누구였나. 방화벽이나 서버 로그에는 주소만 찍힙니다. VPN 기록의 Framed-IP-Address와 접속 시간대를 맞대면 주소가 사람 이름으로 바뀝니다.
  • 같은 계정이 서울에서 접속한 지 20분 만에 다른 나라에서 접속했나. 사람이 그 거리를 그 시간에 움직일 수 없으므로 계정 도용을 의심합니다. 현장에서는 영어 그대로 impossible travel 탐지라고 부릅니다.
  • 새벽에 평소보다 훨씬 많이 내려받은 계정이 있나. Acct-Output-Octets를 계정별로 평소와 견줍니다.
  • 비밀번호를 여러 번 틀린 뒤 성공한 접속이 있나. 인증 실패 기록이 몰린 뒤의 성공은 비밀번호 대입 공격이 통했다는 신호일 수 있습니다.

이 로그만으로는 모르는 것

VPN은 통로를 열어 준 기록만 남깁니다. 통로 안에서 그 사람이 어느 서버에 들어가 무엇을 했는지는 서버의 로그인 기록과 EDR, 방화벽 로그에 흩어져 있습니다. 그 흩어진 기록을 VPN이 알려 준 「주소 = 사람」 표로 묶는 일을 SIEM에서 합니다.
